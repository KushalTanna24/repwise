# Repwise 4.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Steps use `- [ ]`.

**Goal:** Freestyle next-set flow, supplement checklist, collapsible Today, and profile settings with visible effect.
**Architecture:** Pure domain additions (`flow.ts`, `supplements.ts`, planner/session changes) with tests first; thin UI on top.
**Spec:** `docs/superpowers/specs/2026-10-17-repwise-v4-1-design.md`

## Global Constraints
- Done sets are never modified by automation.
- New `AppData` fields are defaulted in `normalize`, so documents saved before this release load.
- Same UI kit and tokens; motion respects reduced motion.

## Review Focus
1. A saved phone document without the new fields must load (normalize test).
2. "Apply to current workout" must not alter any done set (test).
3. `suggestNext` with every set done or skipped returns null (test).
4. Toggling a supplement twice on the same day returns to not-taken (test).
5. Finishers never duplicate an exercise already chosen in the session (test).
